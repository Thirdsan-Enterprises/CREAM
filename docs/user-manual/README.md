# Cream POS user manual

`Cream-POS-User-Manual.pdf` is the manual for the client. `index.html` is its source,
generated by `build_manual.py` from the text in that file and the screenshots in `img/`.

## Why we can say it works

Every step in the manual is run through the real app by `walkthrough/`, on a fresh database:
set up staff, buy at Kira, add an item, transfer, confirm with a shortfall, buy drinks, record
use, sell for cash and on account, take a deposit, change the plate price, reset a password,
add a branch, read the owner's reports. The server side of the same journey is an automated
test: `backend/tests/Feature/ClientWalkthroughTest.php`.

**If you change a screen, a label or a rule, change the manual and rerun the walkthrough.**

## Rerunning the walkthrough

1. Backend: `cd backend && cp .env.example .env && php artisan key:generate`, then
   `php artisan serve` (SQLite is fine).
2. App for the browser, pointed at that backend:
   `cd mobile && flutter build web --release --no-web-resources-cdn --dart-define=API_BASE_URL=http://127.0.0.1:8000/api`
   and serve `mobile/build/web` on port 8081 (`python3 -m http.server 8081`).
3. `cd docs/user-manual/walkthrough && npm i playwright && ./runAll.sh`
   (the browser needs `locale: en-US`, which the scripts set).

The walkthrough drives Flutter's accessibility tree, so controls are found by their labels.
A button with no label cannot be found: give it a tooltip (this is also better for users).

## Rebuilding the manual

Copy fresh screenshots from `walkthrough/shots/` into `img/` (same file names), then:

```
python3 build_manual.py
node render_pdf.js
```
